## 1. 🚨 최우선 — 배포본이 저장소보다 최신입니다

**배포된 사이트에는 있는데 이 저장소에는 없는 기능이 있습니다.**

| 기능 | 배포된 사이트 | 저장소 |
|---|---|---|
| `극장 상영 중` 딱지 (개봉작 카드) | 있음 | **없음** |
| CGV·메가박스·롯데 예매 버튼 (카드·상세) | 있음 | **없음** |
| 개봉 정보 갱신 주기 | "일주일에 한 번" | "하루 한 번" |

저장소 전체 히스토리를 검색해도 `CGV`·`메가박스`·`예매` 문자열이 **한 번도 커밋된 적이 없습니다**
(`git log --all -S "CGV"` → 0건). 브랜치는 `main` 하나뿐이고 stash도 없습니다.

**→ 이 상태로 저장소 코드를 배포하면 극장 기능과 주 1회 갱신이 통째로 사라집니다.**

### 그래서 첫 작업은 이것입니다

1. `mktperiod-a11y/content-site` 의 `main`을 먼저 받아옵니다. 최신 커밋은 아래 2번에 정리돼 있습니다.
2. 그 위에 **현재 배포되어 있는 극장 기능 + 주 1회 갱신 변경을 올려 커밋·푸시**합니다.
3. 충돌 시 원칙:
   - 탭 순서 / 라우트 이동 / 전역 검색 → **저장소 쪽(최신)** 유지
   - 극장 기능 / 갱신 주기 → **배포본 쪽** 유지
   - 같은 파일에 둘 다 있으면 **둘 다 살릴 것**
   - `app/page.tsx` 를 수정했었다면 그 수정은 **`app/search/page.tsx`** 로 옮겨야 합니다(파일이 이동함)

## 4. 발견된 이슈

### 🔴 즉시 처리 필요

**이슈 1. 배포본과 저장소 불일치**
위 1번 참고. 다른 모든 작업의 선행 조건입니다.

**이슈 2. 사이트 주소가 예전 계정 주소로 하드코딩돼 있음**
```
https://q7m4v9x2k8n5.so0yeon.chatgpt.site
```
- `.env.example:14` (`PUBLIC_SITE_URL`)
- `app/sitemap.xml/route.ts:3` (`FALLBACK_SITE_URL`)

계정을 이전했는데 그대로입니다. **구글에 제출되는 사이트맵이 옛 주소를 가리킵니다.**
SEO로 유입을 늘리려는 상황이라 직접적인 타격입니다. 새 주소 확정 후 두 곳 모두 수정 필요.

**이슈 3. `.openai/hosting.json` 의 project_id가 예전 계정 것**
```json
{ "project_id": "appgprj_6a97e2231a0c81919542a27507d63445", "d1": "DB", "r2": null }
```
새 계정 기준으로 갱신이 필요합니다. 또한 D1 데이터는 새 환경에서 비어 있을 것이므로
개봉작 첫 수집이 정상 동작하는지 확인해야 합니다. `KOBIS_API_KEY`, `TMDB_API_KEY` 재설정도 필요합니다.

### 🟡 설계에 반영 필요 (조사로 확인된 사실)

**이슈 4. "최근 60일 개봉작" 필터로는 재개봉작이 전부 누락됨**
CGV 현재상영작 61편 중 재개봉작 11편 이상 확인
(마루 밑 아리에티 2010, 모모와 다락방 2012, 파라노만 2013, 핵소 고지 2017, 곤지암 2018,
델마 2018, 스파이의 아내 2021, 파묘 2024, 퇴마록 2025 …).

**이슈 5. 주 1회 갱신은 상영 정보에 부적합**
국내 극장 상영작은 매주 수·목 대거 교체. 주 1회면 최대 6일간 이미 내린 영화에
"상영 중" 딱지가 붙습니다. 개봉 정보(주 1회)와 상영 정보(하루 1회)를 분리해야 합니다.

**이슈 6. 극장사별 제목 표기가 다름 — CGV만 콜론을 하이픈으로 씀**
```
CGV      스파이더맨-브랜드 뉴 데이
메가박스  스파이더맨: 브랜드 뉴 데이
롯데     스파이더맨: 브랜드 뉴 데이
```
공백 차이도 있습니다(CGV `몬스터섬의` vs KOBIS `몬스터 섬의`).
→ 공백 전부 제거 + 구분자 통일 방식의 정규화 필요. 자세한 규칙은 조사 문서 참고.
다행히 특별관 표기(`4DX`, `자막` 등)는 제목에 붙지 않고 별도 필드입니다.

**이슈 7. 재개봉 개봉일 기준이 극장사마다 반대**
CGV는 **원래 개봉일** + `rrlsYn` 플래그, 롯데는 **재개봉일**을 개봉일로 기록.
→ 개봉일 기준 매칭은 실패합니다. **제목 기준 매칭 필수**, 개봉일은 보조 수단으로만.

**이슈 8. 롯데시네마 응답에 광고가 영화처럼 섞여 들어옴**
`MovieNameKR: "AD"`, `ReleaseDate: null` 인 항목이 실제로 존재합니다. 필터링 필요.

**이슈 9. 메가박스 `movieStatCd` 가 전부 `MSC01(상영중)`**
개봉 예정작(예: `인턴`, 개봉일 2026-09-16)도 상영중으로 나옵니다.
→ 상태 코드만 믿지 말고 개봉일(`rfilmDe`)을 함께 봐야 합니다.

**이슈 10. 수집 실패를 "상영 안 함"으로 단정하면 안 됨**
이 프로젝트가 OTT 제공처에서 이미 쓰는 3단계 원칙을 극장에도 적용해야 합니다.

| 상황 | 표시 |
|---|---|
| 해당 극장사 목록에서 확인됨 | 예매 버튼 활성 |
| 목록에 없음 | 버튼 비활성 / 흐리게 |
| **수집 자체가 실패** | 3개 다 그대로 표시 (단정하지 않음) |

세 번째를 빼먹으면 수집이 하루 깨졌을 때 상영 중인 영화가 전부 "상영 안 함"으로 뒤집힙니다.
수집 실패는 **극장사별로 따로 기록**해서 한 곳이 실패해도 나머지는 정상 반영되게 하세요.

### 🟢 소규모 / 확인만

**이슈 11. 별 아이콘 스타일이 두 화면에서 다름**
- 개봉작 카드: `<Star className="size-3.5 fill-brand text-brand-muted-icon" />`
  → 채우기 색과 테두리 색이 달라 **테두리가 보이고 딱딱한 인상**
- 검색 결과 카드: `<Star className="size-3.5 text-brand" fill="currentColor" />` → 테두리 없음

→ **테두리를 없애고 검색 결과 쪽 스타일로 통일** (확정된 요청 사항)

**이슈 12. `/` 리다이렉트가 307(임시)**
SEO상으로는 308(영구)이 낫지만, 브라우저가 영구 리다이렉트를 캐시하므로
구조를 되돌릴 가능성이 있는 동안은 307 유지가 안전합니다. 구조 확정 후 판단하세요.

**이슈 13. 작업 PC에서 로컬 실행 불가**
Node.js 미설치, `bash` 없음, WSL 배포판 없음.
`package.json` 스크립트가 리눅스 문법(`WRANGLER_LOG_PATH=... vite`)과 `bash scripts/*.sh` 의존이라
윈도우에서 그대로 실행되지 않습니다. **테스트·빌드·배포는 실행 가능한 환경에서 해야 합니다.**
