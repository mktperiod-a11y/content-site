## 1. 커밋 `3445802` — 개봉 예정작 카드 레이아웃 깨짐

### 증상

### 원인
`components/release-catalog-page.tsx` 의 포스터 자리표시자:

```tsx
<div className="grid size-full place-items-center ...">
  <Clapperboard />
  <span>포스터 준비 중</span>
</div>
```

`grid` + `place-items-center` 는 자식 2개를 **서로 다른 암시적 행**에 각각
중앙 정렬한다. 그래서 2:3 비율 박스 안에서 아이콘과 문구가 따로 놀았다.
실측 간격:

| 화면폭 | 자리표시자 높이 | 아이콘–문구 간격 |
|---|---|---|
| 360px | 228px | 92px |
| 768px | 332px | 144px |
| 1280px | 302px | 129px |

`최신 개봉작` 은 TMDB 포스터가 대부분 붙어서 안 보였고,
`개봉 예정작` 은 포스터가 거의 없어서 **목록 전체가 이 상태**였다.

### 수정
- 자리표시자를 `flex flex-col items-center justify-center gap-2` 한 덩어리로 변경
- 아직 개봉도 안 한 작품에 붙던 `구독형 제공처는 상세에서 확인` →
  `개봉 후 제공처가 확인돼요` (카드에 `view` prop 추가). 두 줄 줄바꿈도 사라져

## 2. 커밋 `0b0cb2c` — 상영 정보가 이틀에 한 번만 수집됨

### 증상
`극장 상영 중` 딱지가 들쭉날쭉하고, 상영 정보가 최대 이틀씩 밀림.

### 원인
`last_success_at` 은 수집이 **끝난** 시각이라 크론이 뜬 시각보다 항상 조금 뒤다
(수집에 수십 초 걸림). 그런데 잠금 조건이 TTL 을 정확히 24시간으로 쟀다:

```ts
WHERE (sync_state.last_success_at IS NULL OR sync_state.last_success_at <= ?)
// bind: now - THEATER_SYNC_INTERVAL_MS
```

크론이 매일 T 에 뜨고 수집이 45초 걸린다고 하면:

| | 임계값 | `last_success_at` | 결과 |
|---|---|---|---|
| 1일차 T | — | NULL | 획득 → `T+45s` 기록 |
| 2일차 T | `T` | `T+45s` | **튕김** (45초 차이) |
| 3일차 T | `T+24h` | `T+45s` | 획득 → `T+48h+45s` |
| 4일차 T | `T+48h` | `T+48h+45s` | **튕김** |

→ 격일 수집. "상영 정보 하루 1회" 가 실제로는 안 지켜지고 있었다.
게다가 조회 쪽 신선도 기준이 `INTERVAL * 2` = 48시간이라,
**한 번만 실패해도 즉시 48시간을 넘겨 극장 딱지가 전부 사라진다.**

### 수정
잠금 획득 조건에만 1시간 여유를 뒀다. 화면에 노출되는 `stale` 판정 기준은
건드리지 않았다.

```ts
const SYNC_SLACK_MS = 60 * 60 * 1000;
// ...
now - (THEATER_SYNC_INTERVAL_MS - SYNC_SLACK_MS)
now - (RELEASE_SYNC_INTERVAL_MS - SYNC_SLACK_MS)
```

극장(24시간)·개봉(7일) 양쪽 다 적용. 회귀 테스트는 격일 수집 재현과
수정 후 매일 수집을 둘 다 확인한다.

## 3. 확인만 하고 건드리지 않은 것

`docs/theater-research.md` 의 설계 항목은 이미 코드에 **전부** 들어가 있다.
하나씩 대조했다:

- 극장사 목록을 정답지로 삼고 KOBIS 를 붙이는 구조 — `theater_titles` CTE + LEFT JOIN
- "최근 60일" 필터 폐기
- 극장사별 분리 저장 — `theater_movies` PK 에 `theater_code` 포함
- 제목 정규화 (공백·구분자·문장부호 제거 후 소문자) — `normalizeTheaterTitle`
- 재개봉: 개봉일 아닌 제목 기준 매칭
- 롯데 `AD` / `ReleaseDate: null` 필터
- 메가박스 `movieStatCd` 만 믿지 않고 `rfilmDe` 병행
- 3단계 실패 처리 (`confirmed` / `unavailable` / `unknown`), 극장사별 실패 기록
- 개봉 주 1회 / 상영 하루 1회 분리, 크론 `0 18 * * *`
- 극장 딱지는 3탭에만 (`app/search/page.tsx`), 1탭 카드에서는 제거

이전 인수인계(`docs/handoff.md`)의 이슈 2·3·11 도 이미 반영돼 있다
(사이트 주소, `hosting.json` project_id, 별 아이콘 스타일 통일).

## 4. 남은 과제

### 🔴 데이터 연결

**`KOBIS_API_KEY` 미설정 — `개봉 예정작` 탭이 비어 있음**
`개봉 예정작` 은 KOBIS 에서만 온다. 키가 없으면 레이아웃을 고쳐도 목록이 비어
있다. 빈 상태 화면 자체는 깨지지 않고 "개봉 정보를 준비하고 있어요" 로
정상 표시되는 것까지 확인했다. `TMDB_API_KEY` 도 같이 확인 필요.

**부수 효과:** 키가 없으면 `syncReleaseCatalog()` 가 매번 throw 하고
`last_success_at` 이 NULL 로 남는다. → `stale` 이 계속 true →
`ReleaseRefresh` 가 방문할 때마다 `/api/releases/refresh` 를 자동 호출 →
KOBIS 재시도 반복. 키를 넣으면 자연히 멈추지만, 안 넣을 거면
연속 실패 시 백오프를 넣는 게 맞다. (이번엔 동작을 바꾸지 않고 두었음)

### 🟡 선택 사항

- **`개봉 예정작` 을 KOBIS 없이도 채우는 방법**: 극장 3사의 개봉예정
  엔드포인트가 있다 (CGV 상영예정 탭 67편, 롯데 `moviePlayYN=N`,
  메가박스는 `rfilmDe` 가 미래인 항목). 데이터 소스 추가라 범위가 커서
  손대지 않았다. 필요하면 지시 주면 붙일 수 있다.
- **`lib/ott-plans.ts` 월 요금 실검증** — `PRICES_VERIFIED_ON = "2026-09-04"`.
  공개 배포 전 필수.
- **`theater_titles` CTE 에 신선도 필터 없음** — 의도된 동작으로 보인다
  (수집 실패 시 기존 목록 유지). 다만 스냅샷이 낡으면 1탭 목록에는 남아 있는데
  칩은 사라지는 조합이 나온다. 그대로 둘지 판단 필요.
- **`/` 리다이렉트 307 유지** — 이전 인수인계 판단 그대로. 구조 확정 후 308 검토.
